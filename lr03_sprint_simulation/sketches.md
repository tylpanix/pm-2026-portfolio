# Ескізи перевірених історій

Це текстові ескізи сценаріїв симуляції. Вони показують, що бачить і робить користувач; не є знімками реалізованого продукту.

## S-01: Вхід акаунтом академії

```text
┌─────────────────────────────────────┐
│ Бронювання аудиторій                │
│                                     │
│ [ Увійти акаунтом академії ]         │
│ Після входу відкриється пошук.       │
└─────────────────────────────────────┘
```

Потік: 1) працівник відкриває сервіс; 2) натискає вхід акаунтом академії; 3) після успішного входу бачить домашній екран без запиту на окремий пароль сервісу.

## S-03: Пошук вільної аудиторії

```text
┌─────────────────────────────────────┐
│ Знайти аудиторію                    │
│ Дата [________] Час [____]–[____]   │
│ [Показати вільні]                   │
│                                     │
│ Доступні за сценарієм:              │
│ • 204 — 30 місць                    │
│ • 317 — 24 місця                    │
└─────────────────────────────────────┘
```

Потік: 1) викладач задає дату й часовий проміжок; 2) запускає пошук; 3) переглядає список вільних кімнат. Для цієї історії перевіряється відображення доступних даних; автоматичне джерело лишається окремою заблокованою S-09.

## S-04: Аудиторія та обладнання

```text
┌─────────────────────────────────────┐
│ Нова заявка                         │
│ Режим: (●) Аудиторія  ( ) Обладнання│
│                                     │
│ Аудиторія: 204     Обладнання:      │
│                     [Проєктор ✓]    │
│                     [Мікрофон  ]    │
│ [Далі: перевірити заявку]           │
└─────────────────────────────────────┘

Перевірка заявки:
Аудиторія 204 + Проєктор
[Надіслати одну заявку]
```

Потік: 1) викладач обирає режим аудиторії та задає кімнату; 2) перемикається на режим обладнання й обирає потрібне; 3) повертається до зведення, бачить обидва вибори в одній заявці та надсилає її. Перевірено обидва режими й перехід після додаткових 2 одиниць.

## S-05: Скасування власної заявки

```text
┌─────────────────────────────────────┐
│ Моя заявка №R-12                    │
│ Аудиторія 204 · 14:00–15:00         │
│ Стан: погоджена                     │
│ [Скасувати мою заявку]              │
└─────────────────────────────────────┘

Заявку скасовано. Час знову доступний.
```

Потік: 1) викладач відкриває власну заявку; 2) обирає скасування; 3) бачить підтвердження, що часовий проміжок звільнено.

## S-06: Черга погоджувача

```text
┌─────────────────────────────────────┐
│ Черга заявок                        │
│ R-12 · ауд. 204 · 14:00 · очікує    │
│ [Відкрити]                          │
│                                     │
│ [Погодити] [Відхилити]              │
│ Причина відмови [______________]    │
└─────────────────────────────────────┘
```

Потік: 1) погоджувач відкриває чергу й обирає заявку; 2) погоджує її або вводить причину відмови; 3) бачить результат, який можна показати заявнику.

## S-07: Стан заявки

```text
┌─────────────────────────────────────┐
│ Мої заявки                          │
│ R-12 · 204 · 14:00                  │
│ Стан: Очікує погодження             │
│ Останнє оновлення: після подання    │
└─────────────────────────────────────┘
```

Потік: 1) викладач відкриває власні заявки; 2) обирає потрібну; 3) читає її поточний стан без уточнення в чаті.
